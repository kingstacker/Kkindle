# 大书库、设备扫描与长篇阅读性能优化

本次改动在 dev 分支完成，并保留原有安装器和界面改动。

## 已实现

- 书库刷新复用书籍卡片、目录和已有封面，保持选择状态；封面在后台限并发解码，使用有容量上限的缩略图缓存，卸载时释放图片。
- SQLite 筛选和匹配摘要按数据版本缓存；标题、文件等相关数据变化会使缓存失效，阅读进度变化不再触发全库重算。目录封面查询每个目录最多取三条。
- 同步状态文件按文件身份缓存，书籍和文件建立字典及查找索引，避免每本书重复遍历整个同步快照；保存状态后使缓存失效。
- Windows 和跨平台 Kindle 扫描复用持久化元数据缓存，无封面书籍也可以命中缓存；改变的文件重新读取。枚举和处理移到后台，跨平台渐进刷新按批次报告，设备卡片按路径索引并复用。
- EPUB 建立内容索引在后台串行执行，分块按需生成并支持取消。
- KReader 使用独立排版引擎在后台处理导航、缩放和窗口尺寸变化，过期请求取消，只有最新结果进入界面；重复文本塑形使用有上限的缓存，空白整理改为线性处理。

## 验证

本次针对性回归通过 986 项：基础 897、Windows Kindle 35、跨平台设备 12、App 42。

- 1,000 本无封面书籍首次扫描读取 1,000 次元数据，新服务实例再次扫描读取 0 次，修改一个文件后读取 1 次。
- 250 本书的同步徽标验证了缓存读取及重新同步后的正确性。
- 约 110 万字符内容验证分块偏移及取消；3,000 段正文验证设置重排期间界面响应、最新请求生效和位置保持。
- 自包含 Windows x64 Debug 版已生成并打开。实际检查 70 本书的书库，以及《黄昏分界》884 章书籍的恢复阅读、130%→140%→130% 缩放及正文位置保持。

扩展 UI 回归在停止前执行 141 项，130 项通过、11 项失败。其中本次新增书库选择测试已经修正，并在最后 42 项针对性回归中通过；其余 10 项涉及工具栏布局、设备中文标签、PDF 样式菜单及阅读工具栏自动隐藏，尚未证明是否为既有问题。该扩展运行未完成，不能视为全量 UI 回归通过。

当前没有连接物理 Kindle，S3 同步未启用；设备和同步的大规模验证使用测试数据，尚无真实设备传输和云端吞吐量测量。构建成功，但仍有既有依赖安全警告及 Avalonia 资源警告。
