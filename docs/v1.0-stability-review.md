# v1.0 稳定性审查

审查日期：2026-09-15。代码基线：`c7913e1`，分支 `6-UI-optimization-and-bug-resolution`。

本轮发现并处理了 9 类问题，主要集中在备份和恢复的数据安全、导入的事务完整性、Windows 配置读写，以及 UI 字体的原生崩溃。修复保留在工作区，未创建提交；原有的主窗口界面修改和参考图片已保留。

## 已处理的问题

P1 表示可能丢失数据、损坏恢复能力或导致进程退出，应在稳定版发布前处理；P2 表示特定场景下的功能失败或兼容性问题。

| 级别 | 触发条件与原有影响 | 本次处理 |
| --- | --- | --- |
| P1 | UI 为内置字体生成粗体或斜体时，`SkiaTypeface.TryGetStream` 在原生 `sk_stream_read` 内发生 `0xC0000005`，整个测试进程退出。完整 UI 测试曾在两个不同测试中崩溃。 | 注册专用字体集合，从原始内嵌字体资源创建变体，避开该原生流读取路径；保留真实 Skia 字体对象供渲染使用。 |
| P1 | 备份直接依次复制正在使用的 SQLite 数据库、WAL 和 SHM，不能保证它们来自同一提交状态。 | 使用 SQLite `BackupDatabase` 生成独立的一致性快照；清单数量从快照读取，导出不再包含活动 WAL/SHM。 |
| P1 | 覆盖已有备份时，先截断目标文件；后续读取书籍失败或操作取消会破坏上一次成功的备份。 | 在目标目录的唯一临时文件中完成整个压缩包，成功后才发布，并清理未完成的临时文件。 |
| P1 | 导入备份失败或取消后，恢复操作继续使用已取消的令牌；恢复再次失败时还会删除回滚目录。数据目录与系统临时目录不在同一磁盘时，目录移动也会失败。 | 暂存和回滚目录放在数据目录所在磁盘；逐项记录已移动的原数据；恢复不接受导入的取消令牌；恢复失败时保留恢复副本并在异常中给出位置。 |
| P1 | 导入书籍时，文件记录写入失败，但书籍元数据或默认合集关系已保存；新书会留下空记录，已有书籍也可能被部分修改。 | 单个文件的书籍、格式、合集、封面元数据写入同一事务；失败时回滚并删除本次新建的书籍或封面文件；复制临时文件使用唯一名称。 |
| P2 | Windows 导出的数据库保留反斜杠路径，搬到其他系统后书籍、封面和回收站记录可能无法定位。 | 仅在暂存数据库中规范化路径，包括回收站 JSON 内的路径；兼容缺少新列的旧数据库，源书库不因导出而被改写。 |
| P2 | Windows 上设置文件仍被读取时，覆盖式移动会拒绝访问；修复无效同步设备 ID 时也会在读句柄未关闭前保存失败。TTS 和同步配置的并发保存还会争用固定临时文件。 | 六类设置读取允许删除共享，发布已有配置使用 `File.Replace`；所有相关写入通过目录级锁串行化；保留同步所需的文件时间戳。 |
| P2 | AI 密钥损坏、迁移到其他机器或密钥服务不可用时，可能抛出解密异常，或丢掉原有端点、模型等非密钥配置。 | 在解密边界处理格式、加密和系统密钥异常，仅将不可读取的密钥视为空；保留连接配置和磁盘上的原始文件。 |
| P2 | MDX 解析假设一次 `Stream.Read` 会填满缓冲区；短读取或截断文件会得到错误的长度、数字或数据块。 | 五处读取使用 `ReadExactly`；正常短读取会继续读满，截断输入明确抛出 `EndOfStreamException`。 |

## 复现与验证

本轮新增 20 个核心回归用例和 7 个字体/UI 用例。关键用例先复现原有失败，再验证修复：

- 对 SQLite 注入失败的 `BookFiles` 插入，分别检查新书和已有书籍的回滚。
- 保持未提交的 WAL 写入，检查导出的独立数据库只包含已提交记录。
- 锁住被备份的书籍文件，检查失败导出不会覆盖已有备份。
- 在恢复数据库后取消导入；另行制造 Windows 文件共享冲突，检查二次恢复失败仍保留恢复副本。
- 构造旧版 Windows 路径的备份，检查书籍、封面及回收站恢复。
- 在读取旧配置时并发保存新配置，检查旧快照可继续读取、新配置完整发布；覆盖六类设置。
- 模拟三种密钥读取异常、MDX 短读取及截断输入。
- 在持续 GC 压力下创建 96 个独立字体集合，强制真正生成粗斜体，避免命中缓存掩盖问题；另检查应用实际使用的字体集合及 6 种字体组合。

另修正了 [BookTranslationProgressTests.cs](../tests/Kkindle.App.Tests/BookTranslationProgressTests.cs) 中的测试缺陷：原来的 `Dispatch` 调用把异步操作当作普通返回值，产生 `Task<Task>`，测试框架在断言尚未执行完时便清理应用。现在显式选择异步重载，等待全部断言和窗口关闭完成。翻译进度与字体组合的 8 项专项测试通过；未删除或放宽原有断言。

执行环境：Windows x64，.NET SDK `10.0.400`，Avalonia `12.1.1`，SkiaSharp `3.119.4`，Debug 配置。

## 发布前仍需注意的范围

字体崩溃已被独立测试复现，本次通过改用原始字体资源绕开出错路径。上游原生对象具体如何失效，尚未通过转储或调试器证明；本次不宣称修复了 SkiaSharp/Avalonia 内部所有字体问题。该处理只用于应用内置 UI 字体。

Avalonia 12.1.1 没有公开所需的带模拟样式的字体流工厂，因此该兼容实现通过官方的 `AvaloniaAccessUnstablePrivateApis` 开关访问当前固定版本的字体工厂。实现集中在 `BundledAppFontCollection`；没有升级依赖或修改本地 NuGet 包。后续升级 Avalonia 或更换内置字体时，需要重新执行字体压力、字形样式和完整 UI 测试；待上游提供修复或稳定 API 后，移除该兼容实现及开关。`AVA3001` 提示保留，以免升级时遗漏此约束。

本轮运行了四个测试项目，并检查了备份、书库导入、配置持久化、密钥处理、MDX 解析、字体生命周期及 CI/发布流程。现有回归还覆盖阅读位置与导航、排版、PDF、翻译、拼音、同步、设备传输、设置和窗口交互。以下范围仍需要发布前的集成验证：

- Linux/macOS 的实际运行与跨系统恢复；本轮的路径可移植性通过 Windows 上构造的旧备份验证，没有运行其他系统。
- 真实 Kindle/Kobo 的 USB、MTP 和 WebView 登录/发送流程。
- 真实 S3/WebDAV 服务、外部 AI、邮件、在线下载和 TTS 服务；相关自动测试主要使用本地服务器、临时目录或内存替身。
- 长时间阅读、休眠恢复、磁盘空间耗尽和突然断电。SQLite 快照的一致性不等于数据库与全部外部书籍文件在任意并发修改下都具有同一事务快照。

CI 的开发构建依赖审计设有 `continue-on-error: true`，当前属于信息检查；命令成功也不等于存在漏洞时会阻断发布。建议在稳定版流程中明确漏洞严重度阈值，并让审计不可用或超出阈值时产生可追踪的失败。
